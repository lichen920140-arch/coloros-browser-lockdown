# 禁用ColorOS 系统浏览器

> ⚠️ **风险提示：本文调查并不全面，停用系统组件是有风险的操作。** 结论基于单台设备的静态取证与有限实测，未覆盖全部 ColorOS 版本、机型与使用场景。停用后可能出现：系统入口点了打不开、内置下载/账号/快应用能力消失、访客或多用户空间缺少浏览器。请先评估、先备份、确认能回滚，再动手。

一份关于 ColorOS / realme 预装浏览器 `com.heytap.browser` 的**静态取证、风险分析、停用与回滚**的可复现记录。


1. 这个包到底是什么（59,944 个类的完整 Chromium，不是广告 SDK）
2. 停用它损失什么、保住什么（按"通话/短信/上网/相机/支付/系统更新"逐项判定）
3. 怎么停、怎么验、怎么回滚（含 suspend 与 disable 的差别、双 Package 记录导致的失败）

## 好处

1. **还回约 1 GB 常驻内存** —— 开机即在，不是"用的时候才占"。
2. **断掉三件它自己不会停的事** —— 信息流预取（提前下载内容等你去点）、广告曝光归因上报（`oaid` + 归因域名）、三个免鉴权保活服务（任何应用都能把它拉起来）。
3. **少一个 5.9 万类的特权应用常驻** —— 持 `MANAGE_EXTERNAL_STORAGE`、`QUERY_ALL_PACKAGES`、`PACKAGE_USAGE_STATS`、`REQUEST_INSTALL_PACKAGES`。
4. **少一条完整的广告链** —— 它同时是广告展示位（信息流原生广告）、落地页容器（别的应用的广告点进去落到它）、搜索分成入口。
5. **攻击面变小** —— `AdShowActivity`、`WebExportActivity` 均为 exported 且无权限保护，后者可直接加载任意 URL。

## 坏处

1. **凡是"点名"找它的系统入口全部失效** —— 这些调用不走默认浏览器，而是直接指向 `com.heytap.browser` 或私有 scheme（`heytapbrowser://`、`opluspay://`、`ireaderplugin://`），不会 fallback 到 Chrome，只弹"该应用是由 Shell 所管理"。**这类入口有多少个，本文没有穷举。**
2. **访客模式没有可用浏览器** —— 访客（user 10）里有它、没有 Chrome；分身（user 999）的 `BROWSER` 角色也指向它，但分身里并未安装浏览器。
3. **一些内置能力一起消失** —— 下载器（内嵌迅雷）、快应用桥、书签与账号同步，以及部分 OPPO 系应用内"用浏览器内核打开网页"的页面。最后一项**未逐个验证**。
4. **数据还在，但打不开** —— 书签、历史、登录态仍留在 `/data/data/com.heytap.browser`，只是没有界面读取；`unsuspend` 后原样回来。
5. **不是永久状态** —— `pm suspend` 是按用户（per-user）状态，日常稳定；整包 OTA 重刷 `/product` 或手动 `unsuspend` 即恢复。

## 已知的调查缺口

本文是一份**不完整**的记录，以下三点没有做完，照抄前请自行补测：

- 没有穷举"点名调用 `com.heytap.browser` 或私有 scheme"的系统入口清单，因此无法给出"会坏几处"的确切数字。
- 没有验证 OPPO 系应用内嵌浏览器内核的页面（例如协议页、活动页）在停用后的表现。
- 没有在访客/分身空间内实测开链接的体验，只做了角色与包存在性的静态判定。

## 三条最容易被忽略的结论

1. `pm disable-user` 对"出厂 + 商店更新"双记录的包**会失败**（返回 `new state: default`），要用 `pm suspend`。
2. `suspend` 是**按用户**的状态：`user 0` 之外还有访客（user 10）与分身（user 999），各自的默认浏览器角色要分别看，否则会漏。
3. 停用后"打开链接"是否正常，取决于 `BROWSER` role 指向谁——**不是**看包有没有被禁用。
